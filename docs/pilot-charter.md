# Restricted Beta Charter Template

Complete and approve this template in the organization's controlled system before admitting beta
users. Do not commit employee, customer, credential, incident, or production-data details here.

| Field | Required decision |
| --- | --- |
| Sponsor and accountable owners | Product, engineering, security/privacy, data, operations, release, support, and on-call. |
| Users and duration | Named approved cohort, start/end dates, working hours, and revocation process. |
| Use cases | Bounded coding/productivity tasks and explicit exclusions. |
| Repositories and data | Approved workspaces, Public/Internal classes, providers, memory scopes, and retention. |
| Success measures | Completion/error rate, approved latency/cost, support volume, audit delivery, and recovery targets. |
| Telemetry and notice | Content-free fields, purpose, access, retention, user notice, and privacy approval. |
| Support and incidents | Intake channel, severity definitions, response targets, escalation, emergency disable, and communications. |
| Stop conditions | Security/privacy event, silent audit loss, tenant crossover, uncontrolled spend, critical defect, or owner withdrawal. |
| Evidence | Version/commit, manifest, config digest, matrices, test runs, benchmark, drills, known risks, and approvals. |

At closure, record outcomes, defects, data disposition, credential revocation, tenant offboarding,
support lessons, accepted risks, and the decision to stop, extend, or proceed toward `0.9`.
