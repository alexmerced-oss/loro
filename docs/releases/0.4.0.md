# Loro 0.4.0

Loro 0.4.0 is a correctness, security-hardening, and capability release driven by the
August 10 2026 audit (`roadmap_aug10.md`). Every bug in that audit is fixed, the roadmap's
robustness, performance, testing, and documentation items are implemented, and the seven
proposed features have shipped. It remains alpha software: repository controls are
implemented and tested, while production identity, infrastructure, policy approval, and
assurance evidence belong to each adopting enterprise.

## Highlights

### New capabilities

- **Native provider tool-calling.** A typed tool-schema catalog is published to OpenAI-
  compatible, Anthropic, Gemini, and Bedrock endpoints, so real models can invoke Loro
  tools natively instead of only through the textual `@tool` DSL. Tools whose subsystem is
  disabled are omitted from the catalog. Provider-safe names are mapped back to canonical
  Loro names, and native call IDs/results are preserved across turns. Disable with
  `[runtime].native_tool_calling`.
- **Token streaming.** `loro run --stream` and `loro plan --stream` render model output as
  it arrives via a live display. OpenAI-compatible and Anthropic streams preserve native
  tool calls and use the same proxy, CA, timeout, and retry policy as non-streaming calls;
  unsupported endpoints use a non-streaming fallback.
- **`loro doctor`.** One consolidated pass/fail table across identity, provider, sandbox,
  audit, memory, MCP, and config lint. The previous configuration dump moved to
  `loro config summary`; `loro config` and `loro config show` still print resolved JSON.
- **Compliance queries.** `loro audit query` and `loro audit report` filter the audit chain
  by actor, tenant, event type, action, and time range, and produce a verify-and-summarize
  report. `loro approvals list` presents the approval decisions from that chain.
- **MCP tools as first-class targets.** `@tool mcp.<server_id>.<tool_name>` invokes a
  remote MCP tool directly, under the same approval and audit envelope, so permission rules
  can scope a single remote tool.
- **`loro memory sweep`.** Retires shared memories whose `expires_at` has passed, reporting
  by default and acting with `--apply`; records under legal hold are never swept.
- **`loro config check`.** Reports risky-but-valid configuration — unconfined workspaces,
  `redact` on a persistence surface, name-only sandbox executables, gateway endpoints
  without replay defence, disabled auditing.

### Security fixes

- `artifact.create` is now normalized through `filesystem_resource` and authorized like any
  other write; it previously wrote anywhere on disk with no approval. New `artifact`
  permission key (defaults to `ask`).
- Polaris read-only commands are validated against a per-subcommand option allowlist,
  reject short options and option-like values, and place positionals after `--`. Resource
  normalization now understands `--flag=value`, so catalog-scoped policy rules match.
- Private-key redaction spans the whole PEM block; assignment detection covers
  `PREFIX_API_KEY=`, `AWS_SECRET_ACCESS_KEY=` and similar forms; bare 40-character AWS
  secret keys are detected by shape and entropy; finding previews no longer echo any
  characters of the secret.
- Iceberg tenant isolation uses typed PyIceberg expressions instead of a hand-quoted filter
  string. Postgres search escapes LIKE metacharacters and binds `ESCAPE '\'`.
- Session-message `content_digest` is verified on read; a tampered message is rejected.
- Gateway: signatures are verified before the body is parsed; non-ASCII signature headers
  and deeply nested JSON are rejected instead of crashing pre-auth; Discord timestamps are
  checked for freshness and bridge envelopes require a signed `timestamp`; every request
  path has a top-level exception guard; routes match ignoring the query string; and gateway
  runs inherit managed `required_fields` and `environment_prefix`.
- MCP server mode refuses to export path-reading tools when `workspace_roots` is empty
  instead of exposing any file on the host.
- Bubblewrap profiles bind only declared `readonly_roots` (`filesystem = "minimal"`, the new
  default), unshare the PID/IPC/UTS namespaces, and mask sensitive paths in
  `host_readonly` mode. Name-only executable allowlist entries never accept a binary inside
  an agent-writable root.
- Loader and interpreter variables (`LD_PRELOAD`, `PYTHONPATH`, `NODE_OPTIONS`, …) are
  rejected in both sandbox and MCP environment allowlists.
- MCP transport policy is re-evaluated on every outgoing request, so a redirect cannot walk
  the client off the allowlist or onto a private address.
- `file.search` skips symlinks that leave the workspace, oversized files, and binaries.

### Reliability fixes

- A malformed model tool directive no longer aborts the run: the parse error is fed back to
  the model as a turn and recorded as `runtime.tool_directive_invalid`.
- A full audit buffer evicts the oldest events instead of refusing the newest; evictions are
  counted and reported by `loro audit doctor`. `flush` drains under a single lock, so a
  concurrent append can no longer be deleted.
- Legacy audit files containing a blank line verify cleanly.
- Shared-memory drafts round-trip `expires_at`, so retention applies to committed memories.
- Postgres driver errors are wrapped as `RuntimeError` and fall back to rendering SQL.
- Iceberg `backend-check` requires a configured catalog target.
- Spreadsheet variance formulas reference their own rows; prompts are stored as text, not
  live formulas; artifact filenames carry a timestamp and random suffix so concurrent
  generations cannot overwrite each other.
- MCP task records are written under a lock with a unique temporary file, so the terminal-
  status guard is no longer a TOCTOU; `input_requests` is normalized to `inputRequests`.
- `MCPClient.connect()` no longer rewrites exceptions raised by the caller's body.
- Agentic Graph: `self`, `nodes.self` and `loop` are bound at run time; a missing member
  yields `null`; `==`/`!=` across types is `false` rather than an error; `&&`/`||`
  short-circuit; `+` concatenates arrays; `get()` walks a dotted path; interpolation uses
  the spec stringifier; `%` and `/` by zero and bad `matches()` patterns raise
  `ExpressionError`; parallel node outputs use the right node's contract; loop iteration
  counters survive resume; invalid documents produce findings instead of tracebacks; a
  routing failure or denied node permission blocks that node instead of aborting the run;
  and `graph resume` uses the original workspace and refuses to resume a `--dry-run` plan.
- Atomic, locked writes are standardized across audit buffers, MCP task handles, memory
  drafts and proposals, skills state, and the gateway replay ledger.

### Performance

- `AuditBuffer.append` tracks a cached count instead of re-parsing the buffer per append.
- MCP pagination tracks a running byte total instead of re-serializing all collected items.
- The AGS executor builds `SkillRegistry` and `PermissionEngine` once per run, and the
  run-record and graph schemas are compiled once instead of re-read per save.
- The HTTP audit sink can deliver buffered events in batches (`[audit].http_batch_size`).
  Batching is opt-in; the default of `1` preserves existing collector contracts.

### Diagnostics and documentation

- Graph validation emits `AG901` for fields the schema accepts but the executor does not
  enforce (`gate.timeout_seconds`, `map.max_parallel`, `success.evaluation_order`,
  `failure.escalation`, `policy.on_expression_error`, non-command
  `criterion.timeout_seconds`), so a graph never appears governed by a guarantee the run
  will not honor.
- `docs/audit.md`, `docs/data-protection.md`, `docs/memory.md`, `docs/sandbox.md`, and
  `docs/threat-model.md` now match actual behavior.

## Compatibility

- Python 3.11 through 3.14.
- Existing configuration remains valid. New keys are additive:
  `[runtime].native_tool_calling`, `[permissions].artifact`, `[audit].http_batch_size`,
  `[sandbox.profiles.*].filesystem`/`readonly_roots`/`masked_paths`/
  `trusted_executable_prefixes`, and `[gateway.endpoints.*].require_signed_timestamp`.
- **Behavior changes to review before upgrading:**
  - `artifact.create` now requires an approval decision (`[permissions].artifact`,
    default `ask`) and is confined to `workspace_roots`.
  - Bubblewrap profiles default to `filesystem = "minimal"`. Set
    `filesystem = "host_readonly"` to restore the previous whole-root bind.
  - teams/signal/generic gateway endpoints require a signed `timestamp` in the envelope;
    set `require_signed_timestamp = false` per endpoint to opt out.
  - MCP server mode refuses to start with `agraph.*`/`file.*` exports and no
    `workspace_roots`.
  - Polaris argv is reordered to `resource action [options] -- [positional]`.
  - AGX `1 == true` evaluates to `false` instead of raising, per the AGS 1.0 spec.
  - `loro doctor` prints a health table and exits non-zero on failure; the old output is
    `loro config summary`.

## Release Evidence

The release candidate must pass standard CI, Security Evidence, AGS Conformance, distribution
build/Twine checks, a clean-wheel graph/Skill smoke test, and the tag-triggered Release Evidence
workflow. The release owner must verify checksums and GitHub/Sigstore provenance before PyPI
publication.
