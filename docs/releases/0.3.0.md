# Loro 0.3.0

Loro 0.3.0 adds governed Agentic Graph Specification 1.0 authoring and execution to the enterprise
Python CLI harness. It remains alpha software: repository controls are implemented and tested,
while production identity, infrastructure, policy approval, and assurance evidence belong to each
adopting enterprise.

## Highlights

- AGS 1.0 conformance level 3 with safe JSON/YAML loading, duplicate-key rejection, canonical
  digests, vendored schemas, reference validation, AGX parsing/evaluation, and managed policy.
- Deterministic graph planning with reachability, routing demand, retry/fan-out bounds, projected
  cost, and exact-digest approval before execution.
- Durable graph execution and resume with task, gate, decision, loop, map, and subgraph nodes;
  conditional joins; parallel ready nodes; retries; fallbacks; compensation; and global budgets.
- Harness-evaluated command, file, artifact, human, expression, regex, JSON Schema, LLM judge, and
  governed external criteria.
- Schema-conformant, redacted run records plus identity-bound approvals and hash-chained audit
  events for graph and node lifecycle decisions.
- Model-tier routing with downgrade refusal, minimum-context checks, provider endpoint overrides,
  and effective routing recorded in run evidence.
- `loro graph validate`, `plan`, `policy explain`, `run`, `status`, `resume`, `generate`, and
  `skill-path`, plus `loro plan --format agraph`.
- Read-only `agraph.validate` and `agraph.plan` MCP tools, three Loro-shaped graph examples, and a
  bundled no-script Agent Skill for authoring conformant plans.
- Pinned AGS conformance automation on Python 3.11 and 3.14, with strict example and schema checks.
- Operating-system credential vault references with hidden entry, named accounts, non-secret
  metadata, environment override compatibility, and fail-closed backend diagnostics.
- Authenticated Slack, Discord, Telegram, Teams, Signal-bridge, and generic webhook gateways with
  managed identity mapping, durable replay suppression, bounded asynchronous work, and safe replies.
- Preview-first, digest-pinned Claude and Pi skill compatibility imports with optional reviewed
  Claude MCP configuration translation.

## Compatibility

- Python 3.11 through 3.14.
- Existing 0.2.x configuration remains valid; graph and model-tier settings are additive.
- Existing `loro run` and `loro plan` prompt workflows remain available.
- Graph execution is opt-in through `loro graph`; submitted graphs do not expand permissions and
  remain subject to managed policy, runtime policy, approvals, sandboxing, and budgets.
- Gateway listeners bind to loopback by default and require an approved TLS reverse proxy for
  public ingress. Signal requires an external signed bridge. See
  [Channel Gateways](../channel-gateways.md).

## Release Evidence

The release candidate must pass standard CI, Security Evidence, AGS Conformance, distribution
build/Twine checks, a clean-wheel graph/Skill smoke test, and the tag-triggered Release Evidence
workflow. The release owner must verify checksums and GitHub/Sigstore provenance before PyPI
publication.

The detect-secrets baseline contains 45 visible candidates consisting primarily of configuration
key names, documented examples, and test fixtures. An enterprise release owner and security
reviewer must adjudicate them under organizational policy.

Production deployment also requires the identity, sandbox, DLP, database, Polaris, audit/SIEM,
gateway, distributed-budget, operations, penetration-test, and sign-off evidence listed in
[External Enterprise Requirements](../external-enterprise-requirements.md).
