# Loro 0.5.0

Loro 0.5.0 completes the repository-owned Control Contracts milestone on the road to 1.0. The
release turns previously implicit configuration, approval, audit, compatibility, and release
assumptions into versioned contracts with executable verification.

## Configuration Contract

- Root configuration schema `1.0` is now explicit.
- Existing unversioned configuration is migrated in memory as the supported legacy shape.
- Unknown future schema versions fail closed.
- Every setup/config writer stamps the current root schema.
- The machine-readable support matrix distinguishes supported and experimental surfaces.

## Durable Approval Contract

- `ApprovalStore` defines lookup, listing, creation, and optimistic update behavior.
- The new JSON store persists only approval metadata and digests, never raw arguments.
- Owner-only files, cross-process locking, atomic replacement, size limits, schema validation,
  and compare-and-set consumption prevent partial writes and concurrent one-time replay.
- The in-memory store remains the local default; `loro setup approvals --store json` enables the
  durable single-host implementation.

## Audit And Adversarial Controls

- A typed registry assigns audit events to governed families.
- An AST-based CI check rejects unregistered literal event families.
- The enterprise evidence register is checked for missing, duplicate, unexpected, or invalid
  evidence rows.
- Recalled local and shared memory is explicitly labeled as untrusted context with no user
  authority. A poisoned-memory regression fixture proves embedded approval text cannot directly
  execute a tool.

## Release Evidence

- Release Evidence now creates a clean-environment CycloneDX SBOM.
- The artifact bundle includes `support-matrix.json` and `release-manifest.json`.
- The manifest binds package version, source commit, workflow run, exact artifact hashes, support
  status, known limitations, and evidence documents.
- `SHA256SUMS` covers the wheel, source distribution, SBOM, support matrix, and manifest before
  GitHub provenance attestation.

## Compatibility

- Python 3.11 through 3.14 remain supported.
- Existing unversioned configuration continues to load without user action.
- The default approval behavior remains process-local unless `approvals.store = "json"` is set.
- No model can commit shared memory or grant its own approval.
- Experimental status remains for Iceberg/Polaris production use, MCP/Skills, Bedrock, and remote
  gateways until their later roadmap evidence gates are complete.

## Verification And External Gates

The candidate must pass the complete unit/branch suite, security coverage floors, Ruff,
compileall, Bandit, dependency/license/secret checks, documentation validation, package build,
Twine checks, clean-wheel smoke tests, conformance workflows, and tag Release Evidence.

Corporate assertion verification, signed policy distribution, production Bubblewrap and DLP,
credentialed Polaris/Iceberg authorization, immutable audit collection, protected repository/PyPI
administration, independent security review, and pilot approval remain external enterprise
requirements. This alpha release does not claim those deployment-specific controls are complete.
