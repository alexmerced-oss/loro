# Loro 0.12.0

Loro `0.12.0` completes the repository-defined Open Agent Profile v1 Level 3 harness behavior.
The OAP surface remains experimental and provisional because no immutable canonical upstream
schema, fixtures, revision, or certification suite could be verified for this release.

## Highlights

- Cycle-checked, depth-bounded `extends` composition with deterministic composed digests,
  root-derived trust, lineage reporting, and per-layer least-privilege evaluation.
- Profile-selected MCP servers and Agent Skills, enforced at model-schema publication and again
  at tool execution.
- Explicit, depth-bounded subagent delegation through `agent.run` and `AgentRuntime.run_subagent`;
  child execution receives only the intersection of parent, child, and managed authority.
- Profile-selected `oap-state`, local, and shared memory stores. Shared scopes are intersected with
  the resolved identity tenant and fail closed on mismatch.
- Agentic Graph task nodes can bind a named profile through `x-agent-profile` while retaining the
  graph schema's extension contract and normal graph policy, routing, budget, and audit controls.
- Expanded `loro agents explain` output for lineage, MCP, Skills, subagents, memory, and depth
  ceilings, plus machine-readable provisional Level 3 conformance evidence.

## Security And Compatibility

All new profile fields are additive. Profiles without `extends` retain the 0.11 behavior.
Subagents require an explicit profile list; omission grants no delegation. Explicit empty MCP,
Skill, or memory lists select none. Composed profiles cannot write state directly because a merged
document has no unambiguous persistence target. No-profile runs remain unable to invoke
`agent.run`.

This release does not promote OAP, MCP, Skills, Agentic Graphs, remote gateways, or external
memory backends into the stable 1.0 support promise. Formal upstream OAP certification remains
unimplemented and is stated as such in `docs/oap-conformance.json`.
