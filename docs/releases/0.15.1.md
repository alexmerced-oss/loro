# Loro 0.15.1

Loro `0.15.1` adds an optional local browser workspace without creating a second execution or
policy path. Conversations, profile-backed bots, profile changes, and default settings all route
through Loro's existing configuration, Open Agent Profile, managed-policy, approval, audit, and
AgentRuntime layers.

## Highlights

- `loro web` starts a loopback-only local FastAPI server and bundled React application. The
  `webui` extra keeps the browser stack optional for CLI-only installations.
- Traditional chat supports multiple durable conversations, automatic titles, rename, archive,
  permanent deletion, multi-turn context, streamed assistant output, tool activity, cancellation,
  and approval decisions.
- The Bots view maps profiles to governed assistants and starts conversations pinned to the
  selected profile revision and digest.
- The Profiles view creates and revises project profiles across instructions, model routing,
  tool and Skill access, MCP servers, permissions, workspace roots, memory stores, runtime
  budgets, and writeback behavior. Managed profiles remain read-only and effective authority is
  shown after narrowing.
- Default settings edit the project-local provider, primary model, small model, and default
  profile while preserving managed-overlay precedence and avoiding secret material.
- Conversation transcripts use a versioned SQLite schema with append-only messages and run
  records. The browser resumes prior conversations without treating transcript text as trusted
  authority.

## Security And Operations

Loopback binding is the default. Non-loopback binding requires an explicit IP address and bearer
token supplied through an environment variable. Requests use same-origin validation, a session
cookie, CSRF tokens, restrictive content security and framing headers, bounded session state,
bounded transcript injection, concurrency limits, and one active run per conversation.

Browser approvals cannot exceed the selected profile's effective authority. Session-scoped
approval is offered only when enabled by configuration, cancellation remains cooperative at the
runtime boundary, and profile revision/digest metadata is recorded with each conversation and
run.

## Compatibility

The deliberately limited stable `0.10` core and provisional OAP Level 3 classification are
unchanged. The local Web UI is an additive experimental extension in the support matrix. Existing
CLI behavior and configuration files remain compatible.

## Install

```bash
python -m pip install --upgrade "loro-agent[webui]==0.15.1"
loro web
```

CLI-only installations remain available through `python -m pip install loro-agent==0.15.1`.
