# Loro 0.14.0

Loro `0.14.0` turns the interactive and artifact workflows introduced in `0.13.0` into a more
complete governed harness experience. Setup now discovers real provider catalogs, profiles expose
their authority clearly, REPL turns stream model and tool activity, artifact commands require
authored output, and generated Agentic Graphs can be validated and executed by the harness.

## Highlights

- Provider setup dynamically requests model catalogs across supported providers, with paging,
  search, bundled fallbacks, custom model entry, and an explicit offline discovery switch.
- The profile wizard explains model routes, system instructions, tools, Skills, MCP servers,
  memory, workspaces, permissions, web access, and default-profile selection while preserving OAP
  narrowing rules.
- Plain `loro` presents a responsive parrot-and-status panel, streams assistant output, reports
  tool starts and completions, and keeps durable session metadata visible without batch verbosity.
- `loro docs`, `slides`, `sheets`, and `brief` commands require validated model-authored content by
  default. Placeholder scaffolds are available only through the explicit `--no-ai` path.
- `artifact.create` requires final structured content from the calling agent, preserving data
  protection, formula neutralization, provenance, policy, approval, and audit controls.
- AI graph generation produces a typed workflow that Loro compiles into strict AGS 1.0, validates,
  plans, executes, records, and resumes through the full harness.
- `loro get-started` provides a read-only, context-aware readiness report and focused guidance for
  setup, profiles, the REPL, prompts, artifacts, graphs, memory, tools, and governance.

## Compatibility And Safety

The stable `0.10` compatibility boundary and provisional OAP Level 3 classification are unchanged.
Existing non-interactive provider flags remain supported. Artifact and graph commands no longer
silently substitute placeholder output when a configured model is unavailable or returns invalid
content; use `--no-ai` only when an offline scaffold is intentional.

Web retrieval remains governed by the selected profile, shell permission, web permission, sandbox
executable policy, network mode, and trusted approval. Model-provided approval never authorizes a
tool action.
