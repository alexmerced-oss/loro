# Loro 0.22.0

Unreleased. This page collects changes on the development branch until the release is tagged.

**Release prerequisite:** this release depends on `agent-approval-interchange>=0.2.0,<0.3`.
Publish AAIS library 0.2.0 to PyPI before tagging Loro 0.22.0; until then `pip install` of this
branch cannot resolve the dependency (development uses an editable AAIS checkout).

## Shared AAIS approval store

- The Web UI and stdio approval authority now uses `aais.store.FileApprovalStore` (an
  `ApprovalAuthority` over `FileBackend`) from
  `agent-approval-interchange` 0.2 instead of Loro's own file handling. Pending-request owners are
  recorded as process id, start time and host id, so PID reuse no longer makes a dead owner look
  alive; resolved requests, decisions and owner records are compacted instead of growing without
  bound; event replay reports gaps; a corrupt state file is quarantined and held until
  `loro approvals recovery --acknowledge`.
- New `loro approvals recovery [--cancel-orphaned] [--acknowledge] [--json]`.
- State moves from `.loro/aais-pending.json` to `.loro/aais-approvals.json`; the old file is
  imported once and renamed `*.migrated-<timestamp>`.
- `/api/approvals/events` now returns `{events, gap, compacted_through, latest_sequence,
  store_id}` instead of `{events}`.
- The thread-only concurrency test is replaced by tests that use real separate processes:
  concurrent writers, a cross-process decision waking a waiting process, and a killed owner.
  `loro.process_liveness` is removed; liveness comes from `aais.liveness`.

## Multi-turn context

- Resumed CLI sessions (`loro run --resume-session`, the REPL) and Web UI conversations now send
  earlier turns to the model as native user and assistant messages instead of only the previous
  run's summary (CLI) or one flattened transcript block (Web UI). A new `[context]` section selects
  `mode = "messages"` (default) or `mode = "summary"` for the previous behavior.
- Every history message passes the `model_input` data-protection policy before it is sent.
- When history exceeds `context.max_history_tokens`, the oldest turns are compacted into an
  extractive summary and the compaction is audited as `runtime.context_compacted`. Compaction is
  deterministic and does not call a model.
- Session records gain `messages` and `context_summary` fields. Sessions saved by earlier
  releases resume from their summary once, then continue with native history.
- The Web UI reply footer counts input plus output tokens (it previously always showed 0) and
  says when earlier messages were summarized; a status notice appears while a compacted run is
  in progress.
- Web UI chat layout fixes found while verifying the above: the transcript now scrolls inside the
  chat view so the composer stays on screen in long conversations (it was pushed below the fold),
  long conversation titles truncate instead of widening the view past a phone screen, the composer's
  "Workspace file" and "Upload" buttons are no longer squeezed into send-button squares, and the
  mobile navigation rail fits all ten views at 375px.

## Per-run evidence export (experimental)

- `loro run list`, `loro run export RUN_ID --out run.zip` and `loro run verify run.zip` package
  one run's hash-verified audit slice (with the chain links of the log segment it spans), AAIS
  receipts, configuration and profile digests, tool calls and results redacted by the audit
  data-classification surface, sandbox enforcement status, provider, model and usage. Verify
  exits 1 if any byte was altered; `--expect-digest` and `--audit-log` anchor a bundle to an
  independent record. The format is documented in [Run Evidence Bundles](../run-evidence.md).
- `loro run` prints the run id after each task. Audit `runtime.task_started` events now record the
  model, the resolved configuration digest and the context mode; session records carry the run id.
- A task whose entire prompt is `list`, `export` or `verify` must be written `loro run -- export`.

## `loro run` fixes for brokers

- Fixed: a configuration naming only `provider` and `model` (for example `nous` with
  `deepseek/deepseek-v4-flash`) sent requests to the OpenAI endpoint without a key, so `loro run`
  failed with OpenAI's 401 while `loro providers smoke` succeeded. Model clients now fall back to
  the provider profile's base URL and API key variable; placeholder profile URLs ask for
  `model.base_url`.
- `loro run` exits 1 when the provider fails (it exited 0) or policy blocks the task, prints a
  hint to `loro providers smoke --execute`, and takes `--json` for one machine-readable result.
- The run summary's first line matches how the run ended: "failed" on a provider error, "stopped
  at the step limit" or "stopped at the ... budget" instead of always "completed".
- `loro run --prompt-file PATH` reads large prompts from a file; `-` is rejected because stdin
  carries `--approval-stdio` decisions.

## CLI structure

- The 5,600-line `loro/cli.py` is now the `loro.cli` package with one module per command family
  (no module over 1,000 lines); the former `loro.cli_agents`, `cli_credentials`, `cli_gateway`,
  `cli_graph`, `cli_ops` and `cli_runs` modules moved into it. Command names, options, help text
  and JSON output are unchanged: golden snapshots of all 211 help screens and every `--json` shape
  are checked in `tests/test_cli_golden.py`.
- Fixed: interactive `loro setup gateway` crashed because typer 0.27 no longer exports `Choice`;
  the platform prompt now validates the answer itself.
- The mypy ignore list shrank from 25 to 21 modules.

## Verified identity with OIDC (experimental)

- New `[identity.oidc]`: Loro verifies OpenID Connect tokens itself (discovery, cached JWKS with
  refresh on key rotation, signature, algorithm allowlist that never accepts `none` or HMAC,
  `iss`, `aud`, `exp`, `nbf`, `iat` with clock skew, `nonce` and `azp` for logins). Identities
  gain a `verified` field that is true only for checked tokens, and `auth_method = "oidc"`.
- CLI and runtime: `LORO_ID_TOKEN` supplies the token; `required = true` fails closed.
- Web UI: `loro web --auth oidc` adds a sign-in page, authorization-code + PKCE login,
  HTTP-only session cookies, sign-out, and bearer-token access for API clients. Runs and approval
  decisions are attributed to the signed-in user.
- Gateways: `oidc_audience` on an endpoint requires a bridge bearer token as well as the platform
  signature.
- New optional extra `loro-agent[oidc]` for platforms where `cryptography` is not a default
  dependency.
- Tested against an in-process mock identity provider (discovery, JWKS, authorize, token with
  PKCE checking); no public identity provider was exercised.

## Observability (experimental)

- Optional OpenTelemetry traces and metrics through `loro-agent[otel]` and `[telemetry]`: a
  `loro.run` span with model-call and tool child spans, and counters and histograms for runs,
  tokens, tool calls, latency and approvals. Content is never recorded; with the extra missing
  or telemetry disabled, instrumentation is a no-op.
- Audit forwarding to a SIEM over syslog (RFC 5424, TCP or UDP) as OCSF 1.3 JSON or CEF
  (`[audit.forward]`), best effort so collector outages never block runs, and
  `loro audit export --format ocsf|cef` for backfills. See [Observability](../observability.md).

## Coding tools behind policy (experimental)

- `patch.apply`: all-or-nothing unified-diff application with dry run, conflict reports (file,
  hunk, line, expected and actual text), create/delete/rename, and workspace confinement.
- `tests.run`: detects pytest, npm or cargo, runs it in a new `test-runner` sandbox profile, and
  returns the result line plus the output tail.
- `web.fetch`: allowlisted https domains only, public addresses only (checked at resolution and
  at the connected socket), bounded size and time, text content only; off by default.
- All three go through permissions, approvals, data protection and audit. See
  [Coding Tools](../coding-tools.md).

## Multi-user server mode (experimental)

- Role-based access control for the Web UI API in OIDC mode: viewer, operator, approver and
  admin, from verified role and group claims, with separation of duties (operators cannot
  approve), unclassified routes closed to non-admins, audited denials, and an **Access** view for
  the role matrix and admin-editable claim mappings with lockout protection. The UI hides actions
  a role cannot take.
- `approvals.authority = "postgres"` keeps the AAIS approval queue in Postgres with row-level
  transaction locking, so several processes and hosts share one authority. It is a backend for
  `aais.store.ApprovalAuthority` through the public `aais.backends` protocols (no longer a
  subclass of the file store's internals), passes the AAIS backend conformance kit against
  Postgres 16, and quarantines a row that fails validation until
  `loro approvals recovery --acknowledge`. Tested in containers, including concurrent processes
  and cross-process wake-up.
- Limits: browser sessions are per process, and conversations are shared within a workspace.
  See [Multi-User Server Mode](../multi-user.md).

## Container sandbox backend (experimental)

- `backend = "container"` runs sandboxed commands in a fresh Docker or Podman container:
  read-only root, dropped capabilities, no new privileges, memory/CPU/PID limits, no network when
  denied, read-only workspace mount, and cleanup of timed-out containers. gVisor (`runsc`) is
  used automatically when registered. `loro sandbox doctor` reports the engine, image, runtime
  and whether the engine runs as root. Verified against a real Docker engine. See
  [Sandbox](../sandbox.md#container-backend-docker-podman-gvisor).

## Plugins and hooks (experimental)

- Command hooks (`[[plugins.hooks]]`) run sandboxed before or after matching tool calls; a
  `pre_tool` hook blocks with exit status 2. Entry-point plugins (`loro.plugins`) load only when
  listed in `[plugins] enabled` and can add tools (`plugin.<name>.<tool>`, behind the new
  `plugins` permission) and Python hooks. Hooks can block but never approve or rewrite a call;
  every load, tool call, block and failure is audited. `loro plugins list|doctor` and an
  Extensions section show what is installed. See [Plugins And Hooks](../plugins.md).

## Test infrastructure

- The Postgres backup/restore drill no longer depends on the host's `pg_dump`: when the host
  client is older than the Postgres 16 test server, it runs `pg_dump` and `pg_restore` from the
  `postgres:16-alpine` image instead.

## Graph resume re-asks for redacted params

- `loro graph resume` no longer feeds a redaction marker to a resumed run in place of a real
  value. Before, it refused only when a saved param was exactly `[redacted]`, which only happened
  for params declared `redact: true` (a field the AGS 1.0 schema does not define). The run store's
  data-protection pass can redact just a token inside a longer value, and MagAgent writes
  `[REDACTED]`, so the check missed both. It now finds either marker, or the configured
  `safety.redaction_text`, anywhere in a param value and names the params to supply again.
- New `--param NAME=VALUE` (repeatable) and `--param-file FILE` on `loro graph resume`, next to
  `--params`. In a terminal, missing values are asked for with hidden input; otherwise the
  command exits 2 and names them.
- The executor refuses any param that contains a marker, for runs and resumes alike. Found in
  MagAgent's AGS executor convergence review; see [Agentic Graphs](../agentic-graphs.md).

## Security self-review

The [threat model](../threat-model.md) now covers every 0.22 surface (TM-20 to TM-30) with
assets, STRIDE threats, mitigations, residual risk, and tests. This is a self-review by the
engineer who built the features, not a penetration test. It found and fixed eleven issues, each
with a regression test in `tests/test_security_review.py`:

- `web.fetch` treated NAT64 and IPv4-compatible IPv6 addresses that wrap private IPv4 as public.
- A non-string OIDC `aud` claim caused a server error, and token size was unbounded.
- The web login return path accepted tab and other control characters, an open redirect.
- Telemetry spans recorded exception messages; they now record only the exception type.
- `patch.apply` could read a rename source through a symlinked directory outside the workspace,
  and dry runs read files without read authorization.
- The container backend put environment values on the `docker run` command line, and could mount
  `/`, `$HOME`, or a path containing mount-option separators.
- `loro run verify` read archive members before checking size and member count.
- Plugins installed inside the working directory could claim an enabled entry point name.
- CEF header fields did not escape carriage returns or other control characters.
- `tests.run` accepted runner options that write or delete outside the project, such as pytest
  `--basetemp` and `--junitxml` or cargo `--target-dir`, and absolute or `..` paths.

## Release engineering

- `scripts/check_release_metadata.py` checks that the package version agrees with
  `loro.__version__`, the Web UI package files, the release contract, conformance evidence, the
  README current-release line, the newest released notes and the roadmap milestone table. CI runs
  it as an advisory check on branches and strictly on release tags.
- CI runs `mypy` in a lenient mode over `src/loro`. Modules that do not pass yet sit on a
  per-module ignore list, and a ratchet test only lets that list shrink. Cheap real type errors
  found on the way were fixed: `list`-typed annotations shadowed by methods named `list`,
  Windows-only lock branches now keyed on `sys.platform`, and loose handler and diagnostic types.
