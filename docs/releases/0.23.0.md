# Loro 0.23.0

Release notes — November 7, 2026.

This release fixes bugs found while running the AGS walkthroughs for *Graph Engineering with AI
Agents* (Appendix B). Gate timeouts are now enforced, which is new behavior, hence a minor
release.

## License metadata

- `src/loro/agraph/UPSTREAM.md` said the Agentic Graph Specification is MIT-licensed. AGS code and
  schemas are Apache-2.0 (the specification text is also available under CC BY 4.0). The bundled
  `agentic-graph` and `oap-profile-authoring` Skills now declare `license: Apache-2.0`, matching
  Loro's `LICENSE`, the `pyproject.toml` `license` field and its classifier, which moved to
  Apache-2.0 after 0.22.0. 0.23.0 is the first PyPI release under Apache-2.0; 0.22.0 and
  earlier were published as MIT.

## Managed configuration outranks `--allow-unknown-executors`

- `loro graph validate`, `plan`, `run`, `resume` and `policy explain` turned unknown executor
  extensions on with `--allow-unknown-executors` even when managed configuration set
  `[agraph] allow_unknown_executors = false`. When managed configuration sets the key, its value
  now wins and the flag is ignored with a warning, as with every other managed key. New
  `loro.config.managed_config_data()` and `managed_sets()` expose what managed configuration sets.

## Runtime diagnostic codes match AGS 1.0

- A node whose declared permission Loro does not grant was recorded as `RT021`, which AGS 1.0
  uses for a loop that hit `max_iterations`. AGS defines no code for a refused permission, so it
  is now Loro's `LP012`, and the message names the deciding setting (for example
  `permissions.edit = 'ask'`) and points at `requirements/permissions`.
- An exceeded graph budget was recorded as `RT031` (an output type failure in AGS); it is now
  `RT061`, a global constraint exceeded.
- A loop that hits `max_iterations` now records `RT021` (an error with `on_max_iterations: fail`,
  otherwise a warning).
- Every `fs:` permission, reads included, is still checked against `permissions.edit`, the same
  policy Loro's file tools use, so a read-only node under `edit = "ask"` blocks under `--yes`; the
  `LP012` message names `permissions.edit` as the deciding setting. To allow reads only, add a
  `permissions.rules` entry with `tool = "edit"`, `action = "read*"` and `decision = "allow"`.

## A role-blocked gate says why

- A gate whose `roles` the active identity does not hold was marked `blocked` with no diagnostic,
  so the only way to find out why was `loro identity`. The run record now gets an `LP013` error
  naming the required roles, the roles the identity holds (role names only, no credentials), and
  how to grant one (`[identity] roles` or `LORO_IDENTITY_ROLES`).

## Gate timeouts and `on_reject` are enforced

- `gate.timeout_seconds`, `gate.on_timeout` and `gate.on_reject` were accepted with `AG901` "not
  enforced" notices, and a gate never timed out. They are now applied as AGS 1.0 defines them
  (SPEC 5.5, 7.3 and 15), and validation no longer reports them:
  - `timeout_seconds` falls back to `policy.default_human_timeout_seconds`, and `on_timeout` to
    `policy.on_human_timeout` (default `hold`). The wait starts when the gate is first reached
    (recorded as the gate's `started_at`) and continues across pause and resume. Loro has no
    background scheduler, so a paused gate's deadline is checked when the run is resumed.
  - `fail` fails the gate with a `timed_out` human event and an `LP014` error. `hold` keeps it
    `awaiting_human`, and a late approver can still answer. `escalate` fails closed, because Loro
    has no escalation routing (validation reports `AG901` for it). `approve` is refused by policy
    with `LP015` unless the new `[agraph] allow_approve_on_timeout = true`.
  - A live approver is given only the remaining time. A gate provider that accepts a
    `timeout_seconds` keyword enforces it and raises `loro.agraph.execute.GateTimeoutError`; any
    other provider is abandoned after the deadline. The Web UI's gate now honors the declared
    timeout, and its own 30-minute limit is a timeout rather than a rejection.
  - `on_reject: skip_dependents` marks the gate `skipped` so its dependents are skipped, and
    `on_reject: route` marks it `succeeded` with `outputs.decision` set to `rejected`. `fail`
    stays the default.
- Nodes the scheduler skips because an upstream node failed, was rejected or was skipped are now
  `skipped` in the run record. They stayed `pending` before.

## Maintenance

- The mypy baseline had `loro.artifacts.generation` on its ignore list, but with current
  dependencies the module passed the unrestricted check and failed only the normal one, so the
  ratchet test failed. The payload `TypeAdapter` now carries an explicit type (with a targeted
  ignore for mypy's `Annotated` union limitation), the module leaves the ignore list, and the
  ceiling drops to 20.
