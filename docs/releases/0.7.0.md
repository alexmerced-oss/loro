# Loro 0.7.0

Loro 0.7.0 completes the repository-owned Governed Interoperability milestone on the road to 1.0.

## Highlights

- Sanitized, wheel-bundled contracts for OpenAI-compatible, Anthropic, Gemini, and Bedrock
- `loro providers conformance` for an offline profile and fixture audit
- Managed provider host allowlists and configurable request-correlation headers
- Protected live provider workflow with explicit routes and no implicit fallback
- Frozen MCP revision and Claude/Pi skill compatibility claims
- Hostile MCP downgrade/capability fixtures and graph failure-injection coverage
- Signed-fixture interoperability for Slack, Discord, Telegram, Teams, Signal, and generic bridges
- A machine-readable interoperability matrix included in release evidence

## Upgrade

```bash
python -m pip install --upgrade "loro-agent==0.7.0"
loro --version
loro providers conformance
loro doctor
```

Existing 0.6 configuration remains valid. Provider requests now include `X-Loro-Request-ID` by
default. Administrators can set `allowed_base_url_hosts` and `request_id_header` under `[model]`.

## Deployment-Owned Gates

Production provider residency and rate policy, protected platform applications, TLS ingress,
corporate identity, and immutable audit retention still require evidence from the adopting
organization. See the [Enterprise Evidence Register](../enterprise-evidence.md).
